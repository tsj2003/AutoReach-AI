# AutoReach Live Ops Runbook

Use this when the codebase is ready but the startup still needs the real-world
production pieces: deploy, secrets, DNS, OAuth, Cal.com, Phoenix, warmed
mailboxes, and pilot onboarding.

## 1. Generate Production Secrets

Generate one-time values locally:

```bash
python3 scripts/live_ops_launch.py generate-secrets
```

Set the printed values in Render or your production env store. Do not commit
them to `.env`, docs, tickets, or screenshots.

Required production secrets:

- `AUTOREACH_JWT_SECRET`
- `AUTOREACH_SESSION_SECRET`
- `AUTOREACH_CREDENTIAL_ENCRYPTION_KEY`
- `CALCOM_WEBHOOK_SECRET`

## 2. Configure Render Services

Create the Render Blueprint from `render.yaml`, then set these env vars on the
web, worker, and beat services as applicable:

- `DATABASE_URL`
- `REDIS_URL`
- `AUTOREACH_ENABLE_CONSOLE=0`
- `AUTOREACH_RUNTIME_SMART_DISPATCH=1`
- `AUTOREACH_WORKER_QUEUES=engine,maintenance,standard-agents`
- `AUTOREACH_PUBLIC_BASE_URL=https://YOUR_DEPLOYED_URL`
- `GEMINI_API_KEY`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `CALCOM_WEBHOOK_SECRET`
- `AUTOREACH_CREDENTIAL_ENCRYPTION_KEY`
- `AUTOREACH_PHOENIX_ENDPOINT`
- `SENTRY_DSN`

Keep the credential encryption key identical across web, worker, and beat so
mailbox credentials can be decrypted by dispatch and reply polling jobs.

## 3. Generate The External Setup Plan

Run the planner with your deployed origin and sending domain:

```bash
export AUTOREACH_SMOKE_PASSWORD='choose-a-strong-smoke-password'

python3 scripts/live_ops_launch.py plan \
  --base-url https://YOUR_DEPLOYED_URL \
  --domain YOUR_SENDING_DOMAIN \
  --smoke-email smoke@YOUR_SENDING_DOMAIN \
  --strict
```

The command prints:

- Required env pass/fail checks
- Google OAuth redirect URI
- Cal.com booking webhook URL
- DNS preflight command
- Production smoke command
- Phoenix endpoint reminder

`plan` never prints configured secret values.

## 4. DNS And Mailbox Readiness

Before sending, prove the domain has at least SPF and MX:

```bash
python3 scripts/verify_dns_health.py YOUR_SENDING_DOMAIN --json
```

Then configure DKIM and DMARC through the mailbox provider. Connect at least one
tenant mailbox through Cockpit, start with conservative warmup caps, and verify
mailbox health stays `HEALTHY` before approving pilot traffic.

## 5. Google OAuth

In Google Cloud, add the generated mailbox callback URI to the OAuth client:

```text
https://YOUR_DEPLOYED_URL/api/mailboxes/connect/callback
```

Production mode rejects localhost and foreign-host redirects, so this URI must
match the deployed app origin.

## 6. Cal.com Webhook And Metadata

Create a Cal.com booking webhook that points to:

```text
https://YOUR_DEPLOYED_URL/webhooks/calcom/booking
```

Use the same signing secret as `CALCOM_WEBHOOK_SECRET`.

For every campaign, include booking metadata/custom fields with:

- `tenant_id`
- `engagement_id` or `campaign_id`

Production webhooks without tenant or campaign scope are acknowledged but do not
mutate meetings.

## 7. Phoenix Reasoning Ledger

Deploy Phoenix or use a hosted endpoint, then set:

```bash
AUTOREACH_PHOENIX_ENDPOINT=https://YOUR_PHOENIX_HOST/v1/traces
```

After the first smoke/pilot action, inspect Phoenix for spans from worker tasks
and verify trace IDs also appear in outbox/proof package records.

## 8. Final Launch Gate

Run the command generated by `live_ops_launch.py plan`. It should look like:

```bash
python3 scripts/production_smoke.py \
  --base-url https://YOUR_DEPLOYED_URL \
  --email smoke@YOUR_SENDING_DOMAIN \
  --password "$AUTOREACH_SMOKE_PASSWORD" \
  --company 'Smoke Tenant' \
  --calcom-webhook-secret "$CALCOM_WEBHOOK_SECRET" \
  --exercise-scoped-booking-webhook \
  --secret-denylist "$AUTOREACH_JWT_SECRET,$AUTOREACH_SESSION_SECRET,$CALCOM_WEBHOOK_SECRET"
```

Do not onboard a paid pilot until this passes and Cockpit Operations readiness
shows no required failures.

## 9. Pilot Onboarding Loop

For each of the first 10 pilots:

1. Create the tenant in Cockpit Operations.
2. Run domain preflight and fix DNS before launch.
3. Connect one warmed mailbox and verify health.
4. Create the campaign with cure, signal matrix, budget, and Cal.com URL.
5. Keep HITL approvals on until the customer approves tone and targeting.
6. Review daily mission control: approvals, burned inboxes, budget, replies, CRM sync.
7. Send the proof package after every booked meeting.
